# geocoordinates

Low-level geospatial coordinate primitives for Rust — China datums (GCJ-02/BD-09),
angle encodings, coordinate parsing/formatting, and geodesy utilities. UNIX
philosophy: this crate abstracts **only** geo-related complexity, as primitives for
higher-level libraries to consume (e.g. EXIF GPS extraction lives in a separate
library built on this one).

## Architecture constraints

- **Own the coordinate domain; delegate reference math:** GCJ-02 / BD-09 offset math, DMS / DDM parsing, fuzzy free-text coordinate extraction, locale-aware formatting, frames, and datum transforms are owned here. Heavyweight, well-validated reference math is delegated behind narrow deps (Karney geodesics via `geographiclib-rs`; interchange formats behind cargo features). Polygon / line geometry ops are out of scope — point users at the `geo` crate.
- **Honesty about accuracy:** mark GCJ-02 / BD-09 inversions as approximate (iterative, lossy, decimeter-to-meter) — never present them as exact like a Helmert transform.
- **Axis order is first-class:** GeoJSON / WKT are lon-lat (X,Y); humans and many EPSG CRS are lat-first. Never let it be implicit.
- **Antimeridian and poles:** the two places spatial routines break — handle them explicitly throughout.
- **Round-trip stability:** parse → model → format → parse must not drift.

## Project Conventions

- Prioritize intuitive, language-idiomatic APIs that leverage compile-time checks to enforce correct usage without unnecessary restriction, supplemented by concise inline documentation to resolve any remaining ambiguity.
  - **One canonical path per item:** every public item is reachable at exactly one path besides its `prelude` entry. Implementation modules are private; the crate root re-exports the core types (`Coordinate`, `Crs`, `Height`, `LatLon`, `Approx`, `Length`, `LengthUnit`, `Error`, `ParseErrorKind`, `Result`), and every other item is re-exported flat from its subsystem module (`angle`, `china`, `convert`, `fix`, `format`, `geodesy`, `grids`, `parse`, `dgg`; the feature-gated `parse::interchange` / `parse::sensors` stay modules). Never add a second `pub use` of an item; `mise run public-api-check` fails on one. The prelude never exports `Result` (`pub type Result<T, E = Error>`), so a glob import cannot shadow `std`'s.
  - **Ergonomic types over footguns:** make misuse unrepresentable — datum-tagged newtypes (`Wgs84`, `Gcj02`) over bare `f64` pairs, `Length` over raw meters, `Approx<T>` over silently lossy results — so the compiler catches mixed datums, swapped axes, and exact-vs-approximate confusion at build time. Every public **magnitude** (distance, range, error bound, accuracy, precision, ellipsoid axis, and a height read through `Height::meters`) is a `Length`; a **coordinate component** (lat / lon degrees, easting/northing, ECEF x/y/z, ENU/NED, Baidu Mercator x/y, Helmert translations) stays `f64`, with an `_m` suffix where it is in meters. `Approx<T>` has no `Deref`: its value is read through `value()` / `into_inner()`, never as if exact. Correctness-by-construction must live in **distinct concrete types** (which survive FFI), not in generics or trait bounds (which don't).
  - **Constructor and conversion verbs:** a fallible constructor from primitives is `new`, a `from_*` named constructor, or `parse`; `try_*` (`try_to_x` / `try_from_x`) is reserved for fallible conversions between crate types.
  - **`Coordinate` is passed by value:** it is `Copy`, so APIs take `Coordinate`, not `&Coordinate`.
  - **Option and metadata structs** (`FormatOptions`, `ParseOptions`, `Fix`, `RawSource`) are `#[non_exhaustive]`, built through `Default` plus `const` `with_*` builders (the option structs, which deserialize with `#[serde(default)]`) or a constructor (`Fix::from_coord`, `RawSource::new`), so a field can be added without a breaking change; a metadata struct with an invariant (`Accuracy`) gets the same freedom from private fields behind a validating `new`. FFI-mirrored **data** enums stay exhaustive (see FFI below).
  - Approximate conversions must say so in both the doc comment and (where natural) the name, with a stated error bound.
  - **Valid by construction:** a value type with an invariant (`Coordinate`, `Approx<T>`, `Dms`, `Ddm`, the China newtypes, `Ellipsoid`, `Enu` / `Ned` / `Aer`, `Utm` / `Ups`, `DatumTransform`, `Accuracy`, `Confidence`, `H3Cell` / `S2CellId`, `Mgrs` and the encoded grid codes) keeps its fields private behind a fallible `new` (or named constructor) returning `Result`, exposes read-only getters, and under `serde` deserializes through `#[serde(try_from = "...")]` so no invalid value can be built or deserialized. Conversions out of a valid value are then infallible; there is no public `validate()` on the Rust side (the FFI mirror's `*_validate` functions exist because its records are plain data).
  - **Model-honest names:** a routine that runs on the mean sphere rather than the datum's ellipsoid carries a `_spherical` suffix (`intersection_spherical`, `cross_track_distance_spherical`, `along_track_distance_spherical`) and states its error against the ellipsoid; the unsuffixed name is the ellipsoidal form, on the ellipsoid of the inputs' own CRS (`intersection`, `cross_track_distance`, `along_track_distance`). `haversine_distance` keeps its domain-standard name and states its bound in the doc.
- `Coordinate` deliberately implements neither `Display` nor `FromStr`: a bare string cannot carry the datum and height, so a text round trip would silently relabel GCJ-02 as WGS-84. `format` / `parse_coordinate` (and `parse_coordinate_with`) do not fix that: `format` does not write the datum, `ParseOptions` has no datum field, and parsed text comes back as WGS-84, so a caller round-tripping a non-WGS-84 coordinate through text must carry its datum (and height) outside the string and re-tag the parsed value, e.g. with `Coordinate::new(lat, lon, crs)`.
- All `pub` items need doc comments **with a compiling doctest**; a fallible item's doctest also shows an error case. Mark pure getters / fallible-return types with `#[must_use]` where appropriate.
- Safe rust only. Return typed errors via `thiserror`. Pick the variant by what failed: `Error::OutOfRange` is the latitude / longitude **pair** error, for a position that is not a geographic value at all (non-finite, or outside `[-90, 90]` / `[-180, 180]`); a range error on a single axis or component is `Error::InvalidValue { field }`; `Error::OutsideDomain { operation }` is a *valid* point outside an operation's area of use (UTM beyond 80°S–84°N, UPS outside the polar caps, Baidu Mercator beyond ±74°); `Error::InvalidValue { field }` is any other caller-supplied value or option out of its range; `Error::CrsMismatch` is a coordinate on the wrong datum for the operation (a bare `Crs` *argument* that names no usable ellipsoid is `InvalidValue { field }`, since no coordinate is on the wrong datum); `Error::Parse { kind, detail }` is text that does not read as a position, with the exhaustive `ParseErrorKind` (`Syntax`, `Checksum`, `NoFix`, `Ambiguous`, `Unsupported`, `TooDeep`) saying why, so a caller never matches on `detail`; `Error::InvalidGridRef` and `Error::InvalidCellId` are a malformed grid reference or cell id.
- **Conversion naming:** geometric / projected types (ECEF, ENU/NED/AER, UTM/UPS, MGRS) use `to_coordinate` / `from_coordinate`; discrete cell / encoding systems (Geohash, Plus Code, Maidenhead, H3, S2) keep domain-standard `encode` / `decode`. A **named inherent method is mandatory** for every conversion; `From`/`TryFrom` impls are thin sugar over it — they cannot be the only access path, because they cannot cross FFI.
- **serde:** under the `serde` feature, derive `Serialize`/`Deserialize` on every value / option / id type (coordinates, enums, config structs like `FormatOptions`/`ParseOptions`, ids like `S2CellId`). Skip only purely behavioral types.
- **FFI translatability (UniFFI):** the separate `geocoordinates-ffi` crate exposes the public API across the FFI boundary with **full capability parity** (Python, Kotlin, Swift, and TypeScript/WASM; Java consumes the Kotlin/JVM artifact, and TypeScript is generated with `uniffi-bindgen-react-native` targeting wasm32 — see `crates/geocoordinates-ffi/web/`). Parity is per **capability**, not per signature: every public capability must be reachable through one canonical FFI form, but not every Rust-side overload, trait impl, or operator. The FFI mirror **gates every release** — a milestone is not done until its surface crosses the boundary.
  - Design rule: every new public capability gets an **FFI-expressible canonical form** (named inherent methods or free functions over concrete types); Rust idioms are thin sugar layered on top. These idioms **cannot** cross FFI: generics (`Approx<T>`), traits and `impl Trait` bounds (`LatLon`), `Deref`, operator overloads (`Length`), and `From`/`TryFrom` conversions. Their FFI forms are flattened concrete records (e.g. `ApproxWgs84 { lat, lon, max_error_m }`), free functions in place of trait methods/operators/conversions, and primitives in place of wrappers (distance as `f64` meters). `SystemTime` crosses natively (UniFFI's builtin `Timestamp`), so `Fix` metadata is FFI-clean. Keep exported names language-neutral and preserve exactness semantics across the boundary (retain `_fast`/`_refined`). Every export follows the naming scheme in `crates/geocoordinates-ffi/README.md#naming`: a unit suffix on every returned bare length (`_m`) and angle (`_deg`), `parse_*` for every reader, a `<record>_validate` for every invariant record, `<grid>_canonicalize` for every grid code, and `# Errors` on every fallible export (`tests/export_coverage.rs` enforces it, and that every export has a Rust test).
  - Mirror sync is compiler-enforced: FFI-mirrored **data** enums (`Crs`, `LengthUnit`, …) are exhaustive (no `#[non_exhaustive]`), so adding a variant fails the FFI crate's build until the mirror + its `From`/`Into` impls are updated. Mirror wildcard arms are allowed **only** where the fallback preserves meaning (errors → `GeoError::Other { detail }`), never where they would mislabel data (datums, units). `Error` alone stays `#[non_exhaustive]`.
